Version: 1.0. Preserve the 100 stable check IDs. Score each row 0/1/2 using
scoring.md; the last column describes applicability, not a score. An observable
absence is 0. Use `U` for an unavailable test/input and `NA` only with an
applicability reason. Each check's description is the anchor for a clear 2.

## BQ — Experience-bullet quality

Audit every bullet's six components separately; summarize these checks at the
domain level using the relevant bullets. Do not let one strong bullet conceal
systematically vague ones. Do not average component checkboxes into this score.

| ID | Observable check / anchor for 2 | Applicability |
| --- | --- | --- |
| BQ01 | Use clear, accurate action verbs identifying the candidate's work. | Experience bullets; include research/volunteer work |
| BQ02 | Identify the object: system, process, problem, project, or deliverable. | Experience bullets |
| BQ03 | Explain relevant methods, tools, or collaboration where they clarify the work. | Bullets where method matters |
| BQ04 | State scope/responsibility where needed to judge the claim. | Scope-relevant bullets; qualitative scope is valid |
| BQ05 | Show supported results, outputs, or enabled capability where material. | Result-relevant bullets; metrics not mandatory |
| BQ06 | Make the work's relevance to the target role evident. | JD/target |
| BQ07 | Usually include action + object + at least one of method/scope/result. | Experience bullets; heuristic with reasonable exceptions |
| BQ08 | Keep numbers, impact, and causal language traceable and non-contradictory. | Metrics/outcome claims; do not demand external verification |
| BQ09 | Match verb strength to supported ownership; distinguish assisted/built/led. | Experience bullets |

## RS — Recruiter scan

Run a top-third/approximately 10-second scan as a usability heuristic. Answer
first, then inspect carefully. Do not claim a measured recruiter study or time
experiment when none was performed. Text-only input supports a content scan,
not a layout scan.

| ID | Observable check / anchor for 2 | Applicability |
| --- | --- | --- |
| RS01 | Identify the target role immediately and correctly. | Target/JD for correctness |
| RS02 | Identify three strongest relevant, supported qualifications quickly. | Target/JD; do not invent three if fewer are supported |
| RS03 | Identify the most compelling supported result/output quickly. | Resume; no result visible = 0 |
| RS04 | Identify relevant usable tools/methods quickly. | Target/JD |
| RS05 | Identify the demonstrated level of responsibility quickly. | Resume |
| RS06 | Understand the timeline quickly without assuming overlaps are errors. | Dated entries |

## Priority workflow and applicability

Apply section 10 of the user's audit as seven ordered fix tiers in SKILL.md.
Do not score it as a tenth quality domain. Keep explicit required-condition
uncertainty visible even when presentation scores are strong.

For all rows: distinguish an actual missing qualification from missing written
evidence. Use `NA` for a truly irrelevant feature (e.g., absent optional summary,
no certifications expected or claimed). Use `U` for missing JD, original file,
render inspection, inaccessible links, or unknown submission constraints. Record
the reason and what would allow assessment. Never omit a row silently.

# Evaluation report structure

Use concise prose up front and tables for exact mappings. Scale the detail to the
request while preserving the complete check record for a full audit. Do not fill
placeholders with invented facts. Avoid a generic disclaimer wall.

## 1. Conclusion and boundary

Identify target, input version, and mode. State what the resume currently proves,
what is under-evidenced, and the most consequential uncertainty. Name the three
strongest supported qualifications (or fewer if necessary). Separate document
clarity from underlying qualifications. Do not issue a hiring recommendation.

State inspection status explicitly:

| Test | Status and evidence |
| --- | --- |
| Visible layout | Checked / unavailable; pages or image supplied |
| Local text extraction | Checked / unavailable; method and reading-order findings |
| Employer ATS import | Observed / not observed; do not imply vendor simulation |
| Target requirements | Exact JD / role hypothesis / unavailable |

## 2. Highest-impact revisions

List up to five immediate actions in the user's priority order. For each include
source locator, exact edit/action, reason, and whether confirmation is needed.
Keep actual learning/credential requirements outside the editing checklist.

## 3. Five job-description lists

Use the five categories from SKILL.md. Preserve exact requirement logic and
required/preferred/contextual/ambiguous labels. Give IDs and JD locators. State
`Not specified` for empty categories. List explicit application conditions
separately, with timing and unknowns rather than guessed eligibility.

## 4. Requirement-to-evidence matrix

| ID | JD requirement and strength | Exact/alias coverage | Resume evidence and locator | Evidence 0–2/U | Relationship and gap type | Action |
| --- | --- | --- | --- | --- | --- | --- |

Include every required/preferred item and major duty. Combine alternatives only
when the JD does; deduplicate cross-category requirements. Summarize supported,
partial, not-evidenced, contradicted, and unknown counts separately for required
and preferred groups. Highlight unresolved required facts regardless of scores.

## 5. Category score profile

| Domain | Points / possible | Scored / NA / U | Assessment coverage | Main finding |
| --- | --- | --- | --- | --- |

Include KW, PS, JM, SP, BQ, PR, SK, ED, RS with full domain names. Mark partial
results. Explain 0/1/2 and NA/U once. Include no overall number by default. If one
was requested, use scoring.md and disclose the aggregation convention.

## 6. Bullet and project findings

For each experience bullet provide a compact A/O/M/S/R/Relevance record using
0/1/2, NA, or U, an evidence locator, and a material improvement when needed. Do not
turn missing optional components into automatic failures. Provide every
project's contribution, stack/method, workflow, output/status, evaluation, and
any applicable reliability/delivery/link findings. Identify strongest evidence
as well as weaknesses. Keep job-context uncertainty visible.

Provide a few targeted before/after rewrites using only source-supported facts.
State which facts each rewrite preserves. Put any proposed but unconfirmed
outcomes/tools/scope in separate fact-gathering questions, never final bullets.

## 7. Recruiter scan answers

Answer six questions from the top-third/content scan and distinguish subsequent
full-read discoveries: target role, three strongest qualifications, strongest
result/output, tools/methods, responsibility level, and timeline. Mark anything
not immediately apparent. Label 10 seconds as a review heuristic.

## 8. Complete 100-check appendix

| ID and check | 0/1/2/NA/U | Evidence and locator | Reason and fix |
| --- | --- | --- | --- |

Include all 100 stable IDs, including NA/U reasons. Group by domain. An audit JSON
can carry machine-readable fields, but do not replace the entire requested
assessment with a raw JSON dump. For a long resume, a separately requested/saved
report may hold the full appendix while the conversation contains key findings.

## 9. Uncertainties and research basis

Ask at most three high-value fact questions (unless the user requests a detailed
questionnaire). Identify missing JD/file/pages/observations. Cite only sources
actually consulted for external ATS/research claims and distinguish heuristics
from vendor behavior. Resume evidence uses private document locators, not web
citations. Do not claim browsing, link validation, file inspection, or arithmetic
execution that was not performed.
